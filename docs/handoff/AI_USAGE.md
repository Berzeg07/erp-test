# AI_USAGE

В продукте живой модели нет: черновик письма собирает код из evidence, «совет» LLM — локальный mock без ключей.

## Как работал

Разработку вёл в **Cursor IDE**: агент в чате помогал набирать модули, тесты и экраны по срезам. Я оставался оркестратором: фиксировал стек и границы системы, архитектуру (один API, одна админка, два tenant), контракт полей после ответов HR, code style каркаса (FSD на админке, Zod в `@app/shared`, тесты на ошибках и auth), нарезку срезов в `docs/dev/coding-slices.md`. Каждый срез смотрел сам: code review, прогон сценариев (изоляция, kill-switch, approval, CRM/DLQ), правки, если поведение расходилось с ТЗ.

В репозиторий не попадали боевые ключи, реальные контакты и письма сверх синтетических фикстур.

## Где помогал ассистент

- Каркас и доменные модули сервера (импорт → метрики), контракты Zod, HTTP-тесты включая матрицу из 18 пунктов.
- Демо-экраны `apps/admin` под немую раскадровку.
- Черновики документов сдачи — я правил формулировки и цифры

Ассистент не заменяет проверки границ: tenant-фильтр и approval закрыты тестами, не «словом модели». Скринкаст снимаю сам по `docs/dev/screencast.md`.

## Что в продукте не делегируется модели

Текст исходящего письма не генерирует внешний LLM. Канал и CTA задаёт политика. Основание обработки (`processingBasis`) ставят правила, не совет mock-модели.
